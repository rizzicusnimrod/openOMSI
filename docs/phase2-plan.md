# Phase 2 plan: the world looks real

Fork-only planning notes (branch `custom`). Phase 1 "nature" is done (commit
5ee23e2: wind sway, lightning, contact shadows, seasonal foliage, rainbow,
headlight fixes). Phase 2 is NOT started: this file is the input for an
implementation plan. Nothing here is built yet.

## Items

| # | Feature | Why | Size |
|---|---|---|---|
| 2.1 | **Sun shafts in fog and forest** (volumetric fog lit through the sun's shadow map) | TH_Wald at dawn with light beams through the trees. | L (but see findings: may be tuning) |
| 2.2 | **Real reflections**: screen-space reflections plus a local reflection snapshot around the bus every few frames | Bus paint and windows reflect only the sky now. Outside Enhanced+, only puddles get screen-space reflections. | M-L |
| 2.3 | **Grass on verges and fields**, generated on grassy ground, swaying (reuse phase 1 wind sway), fading with distance | OMSI's grass ground is a flat texture | L |
| 2.4 | **Auto relief for old textures**: a soft normal map made from the brightness of cobbles, brick and bark, with per-map overrides like `retroreflective.cfg` / `foliage.cfg` | OMSI textures look flat up close | M |
| 2.5 | **TAA** (temporal anti-aliasing), so MSAA can drop from 8x to 2-4x | Fixes shimmering thin branches; MSAA 4x alone measured +7 fps by day | L |
| 2.6 | **Sunlit cab**: sun patches moving over the dash and floor, cab light coming from the windows | The cab has one flat ambient now (`cab_e`) | M |
| 2.7 | **Tracks in wet and snowy roads**: drier tyre lines as the road dries, tracks and slush in snow | `snow_cover` / `snow_depth` exist but roads stay uniform | M |

Suggested order (from the original plan): 2.1 and 2.2 first (biggest visible
jump for the effort), then the rest.

## Code findings so far (2026-10-20, read-only check)

- **2.1** Sun shafts already exist: `sun_shafts` in
  `crates/omsi-render/src/fog_lamps.wgsl` (from upstream 0.2). So 2.1 is
  mostly tuning/extending (forest + ground fog, shadow-map sampling quality),
  not a new pass. Check what it does before planning new work.
- **2.2** In Enhanced the reflection probe captures only the sky. Enhanced+
  (ray tracing, `rt_reflect.wgsl`) already writes the surface inputs a
  reflection pass needs, and the puddles already have a screen-space trace
  (`puddle_reflection.wgsl`, `puddles.rs`) to reuse. Medium work.
- **2.3** Nothing to build on: no grass handling anywhere in the code.
- **2.5** Camera jitter (`view_shift`, used by photo mode) and last-frame
  camera data exist. AI cars and other moving objects have NO motion vectors,
  so they would ghost/smear under TAA - needs per-object previous transforms.
- **2.6** Enhanced lights the cab with one flat ambient (`cab_e` in
  `enhanced.wgsl`). The close sun shadow cascade is the starting point for
  sun patches.
- **2.7** Road wetness model lives in `crates/omsi-app/src/puddles.rs`;
  `snow_cover` / `snow_depth` are read by `snow.wgsl` and render lib.rs.

## Limits that shape every item

- No new art: OMSI 2's old models/textures cap the look, so gains come from
  light, air, motion and wetness. Anything new is generated by code (no
  licence problems).
- No spare GPU time. User's PC: Ryzen 5 3600 + RX 6700 XT, 2560x1440,
  Enhanced, MSAA 8, AF 16, shadow 4096, mirror 512, render scale 1.
  TH_Wald terminus: day 42-44 fps (CPU main thread ~ GPU ~22 ms, balanced);
  night rush 24 fps, GPU-bound (36.8 ms, main pass 25 ms). Every effect needs
  a quality setting and an off switch; TAA (2.5) could pay for others by
  allowing lower MSAA.
- Phase 0 (performance: merge spline draws, one shared depth prepass, light
  grid once per frame, cheaper AI beams) was skipped by the user.

## How the code is built here (mirror this)

- Each feature in its own new file (like `foliage.rs`, `lightning.rs`,
  `wipers.rs`, `events.rs`, `cinema.rs`); new shader code in its own
  `.wgsl` where possible (like `blockers.wgsl`). Keeps upstream merges
  manageable (last trial merge: 20 conflict spots, mostly the renderer).
- Settings in all four places: `crates/omsi-app/src/settings.rs`,
  `crates/omsi-launcher-core/src/lib.rs` (parse/write), in-game rows in
  `game_lists.rs`, page layout in `settings_layout.rs` (+ launcher
  `launcher/pages.rs`). See phase 1's `wind_sway` / `seasonal_foliage` /
  `lightning` for a full example.
- Switches: `OMSI_NO_<X>` off switch for A/B, `OMSI_DEBUG_<X>` log switch.
- Per-map rule files like `assets/foliage.cfg` / `retroreflective.cfg`
  (`retro.rs` `Rules::matches` + `map_rules`).
- Tests: unit tests inside each file; a CPU copy of shader math where it is
  tested (like `headlamp_profile` in omsi-render lib.rs). Uniform structs
  must stay in sync across all wgsl copies (e.g. `Camera` exists in 4
  structs) and with Rust `bytemuck` sizes.
- Grading/new effects are Enhanced-only unless noted.

## Validation

- Unit tests (Windows target on the user's PC):
  `cargo test --release --target x86_64-pc-windows-msvc -p omsi-app -p omsi-render -p omsi-content -p omsi-launcher-core`
  (phase 1 counts: app 632, render 52, content 18, launcher 43).
- On Linux / cloud: `cargo check` and the same tests without `--target` may
  work for the pure crates; the game itself, offscreen renders and GPU
  benchmarks only run on the user's Windows PC.
- Visual checks (user's PC): offscreen shots with `D:/dev/vistest/shot.sh`,
  frame times with `D:/dev/perftest/bench.sh` - compare profile stage ms
  (`OMSI_PROFILE=1`, `OMSI_GPU_TIMERS=1`), not fps.
- "Beautiful" is judged by the user in the game: before/after screenshots,
  then a live check.
